# Report format

## Header

```
# PR Review — <date>
3 groups · 6 PRs (4 requested, 2 mine) · 1 changes · 1 comment · 1 approve · 2 unchanged
```

The requested and mine counts come from `queue.jsonl` and include unchanged and skipped PRs. If mine is above 0, at least one `(mine)` group, Unchanged line or Coverage gaps line must name them.

## One section per group, worst verdict first

Heading: `### <TICKET> — <short description>  <verdict>`. Write the description yourself in about six words, from the diff, not the PR title. Add `(mine)` after the description for groups I authored.

Every group gets a table, even a single PR. Order rows by repo, then PR number.

```
### BOUN-11317 — Cron-driven survey auto-close  💬 comment

| Repo          | PR                              | Author      | Verdict    | Blocking | Nits |
|---------------|---------------------------------|-------------|------------|----------|------|
| cron-api      | [#677](url)                     | @EmadNazzal | 💬 comment | 0        | 1    |
| dashboard-api | [#2062](url) _stacked on #2041_ | @EmadNazzal | 💬 comment | 0        | 3    |
| ts-types      | [#628](url)                     | @EmadNazzal | ✅ approve | 0        | 0    |

**Not reviewed (not requested):** dashboard-api #2041, the stack parent. Context only.

**What it does.** One or two lines in your own words, from the diff.

**Merge order.** ts-types #628 → cron-api #677 → dashboard-api #2062. Reversing the last two breaks prod: the dashboard reads `closedBy` before cron emits it.

**Blocking**
- [`dashboard-api/src/routes/close.ts:88`](https://github.com/bounceinsights/dashboard-api/blob/<full-head-sha>/src/routes/close.ts#L87-L89): loads the survey by `:id` with no tenant predicate; any logged-in user can close another tenant's survey.

**Nits**
- [`cron-api/src/jobs/close.ts:44`](...): `Promise.all` over every open survey with no concurrency cap.

**Questions**
- Is `closedAt` still read by any external integration?

**Recommendation.** Request changes on #2062; #628 and #677 can merge independently.
```

- Link each location to GitHub with the **full head SHA** and a line range with one line of context either side.
- Omit empty Blocking / Nits / Questions headings. Mark drafts `_draft_`.
- A single PR with no findings: the table plus **What it does** and "No findings."
- The **Not reviewed (not requested)** line goes directly under the table and only ever names a PR outside the table, so nobody reads it as "a requested PR was skipped".

## Verdicts: derive them, don't judge them

- **Row**: any blocking → `🔴 changes`; else any nit or question → `💬 comment`; else `✅ approve`. A row with `Blocking 1` and `💬 comment` is a contradiction.
- **Group**: exactly the worst row verdict in its table.
- **Header counts** must add up to the rows. If `changes + comment + approve ≠ reviewed PRs`, recount before writing.

## After the groups

**Unchanged since last review**: one line per PR whose head SHA matches `state.json`:
`- dashboard-api #2232 — 💬 comment on 2026-10-20, no new commits`

**Cross-group stack chains**: only when a chain crosses ticket groups:
`admin-v2: #638 → #639 (BOUN-11331) → #640 (BOUN-11332). #640 has a blocking finding, so approving BOUN-11331 doesn't unblock it.`

**Coverage gaps**: always present, even if empty. List:
- `MISSING`, `NO-BASE`, `STUCK`, `BEHIND`, `FETCH-FAILED` lines from `sync-repos.sh`, and what that means for the review.
- Consumers swept only by `gh search code` (default branches, may lag), not by a local grep.
- PRs not reviewed and why (base unresolvable, no readable tree, my stale drafts).
- Findings trimmed by the 8-per-PR cap.

## Posting rules (only when I ask after the report)

- Post a review with `gh api repos/bounceinsights/<repo>/pulls/<n>/reviews` using `event: COMMENT`, the head SHA as `commit_id`, and inline `comments` on the right lines. Never `APPROVE` or `REQUEST_CHANGES` unless I say so.
- Use a `suggestion` block when there's a concrete replacement:
  ````
  ```suggestion
  this is my new suggestion
  ```
  ````
- No "Generated by Claude Code" footer, no emojis in comments.
- Prefix nits with "Nit:". Questions are phrased as questions.
- Show me the exact comments before posting, since they go out under my name.
