# Live check format

One section per group. Inside today's report it goes under the group's section, before **Recommendation**, as `#### Live check`. In `$LIVE/<group>/results.md` it starts with the group heading from the report (or `### <TICKET> — <short description>` if the group isn't in it).

```
#### Live check  2 pass · 1 fail · 1 blocked

_Ran dashboard#3982 in review-tool on 2026-11-27 (entry PR; dashboard, dashboard-api and retrieval-engine-v2 up; retrieval-engine-v2 started by hand per the PR's setup)._

| # | Check | Source | Persona | Expected | Actual | Result |
|---|-------|--------|---------|----------|--------|--------|
| 1 | Ask with no tags | PR step 7 | globex.root | 4 recommended | "Recommended (4)" | ✅ PASS |
| 2 | Tag picker filters sources | PR step 9 | globex.root | only Fans sources | 3 rows, all tagged Fans | ✅ PASS |
| 3 | Other org's tag id in `tagIds` | Finding: no org check | acme.member | 400 | 200, 2 Globex sources | 🔴 FAIL · reproduced |
| 4 | Flag off | Regression | client_user | no Tags button | — | ⛔ BLOCKED: flag forced on in growthbook.js |

**Failures**
- **3**: `POST /sources/retrieve` with a Globex tag id as Acme returned 200 and two Globex sources. Cause: [`retrieval-engine-v2/app/tag_scope.py:41`](https://github.com/bounceinsights/retrieval-engine-v2/blob/<full-head-sha>/app/tag_scope.py#L40-L42) checks the tag exists but not its `orgId`. Video: `3-other-org-tag.webm`.

**Blocked**
- **4**: the PR forces `retrieval-engine-tags` on in `src/config/growthbook.js`, so the flag-off path can't run without editing the checkout.

Videos: `~/review/.code-review/live/2026-11-27/BOUN-12045/`
```

- The heading counts add up to the rows. Count `UNVERIFIED` as its own term when there is one.
- Result values: `✅ PASS`, `🔴 FAIL`, `⛔ BLOCKED: <why>`, `❔ UNVERIFIED`. Finding checks add `· reproduced` or `· not reproduced`.
- Actual quotes what you saw, briefly. It's never "works" or "as expected".
- Omit empty **Failures** / **Blocked** lists. Give each failure the request, the response, the cause anchored with the full head SHA, and the video file name.
- A finding not reproduced but not refuted stays in the code review section. Say so under the table in one line.
- Never include passwords or tokens.

## Posting rules (only when I ask after the run)

- Post with `gh pr comment <pr> -R bounceinsights/<repo> --body-file <file>` on the PR the failure belongs to, with one `--attach "<path>#Check <n>: <short result>"` per FAIL video or screenshot (gh 2.99+).
- Attach only failing checks. Replace local paths with file names, and end with one line saying the other recordings are available on request.
- Leave out files over GitHub's size limit and tell me which to drag in.
- No emojis in the comment, and no "Generated by" footer.
- Show me the exact comment and attachments before posting, since it goes out under my name.
